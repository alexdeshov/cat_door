# История рабочей сессии — 2026-07-27

## Цель сессии

Подготовить первый локальный прототип CatDoor AI для двух камер, ручной записи и
разметки проходов, а также создать основу локального обучения и независимой
приёмки ONNX-моделей.

## Выполненные этапы

### 1. Подготовка Windows

- установлен Git for Windows;
- установлен FFmpeg/ffprobe;
- создано виртуальное окружение Python 3.13;
- установлены runtime- и dev-зависимости проекта;
- установлен и авторизован GitHub CLI.

### 2. Проверка камер

- проверена Ivideon V Ursa Minor через локальный RTSP;
- проверены основной и дополнительный H.264-потоки;
- обнаружена и проверена Ivideon Cute 2 в локальной Wi-Fi-сети;
- подтверждены основной и дополнительный H.264-потоки Cute 2;
- пароли и полные RTSP URL сохранены только в локальном `.env`.

Итоговые роли:

- центральная камера (`face`) — Ivideon Cute 2;
- дополнительная камера (`side`) — Ivideon V Ursa Minor;
- центральное изображение развёрнуто на 180° только в веб-интерфейсе.

### 3. Локальная админка MVP

- FastAPI application factory;
- MJPEG-превью обеих камер через локальные процессы FFmpeg;
- параллельная запись `face.mp4` и `side.mp4`;
- SQLite-модель событий и последовательные SQL-миграции;
- журнал событий и воспроизведение двух роликов;
- ручная разметка `known_cat`, `foreign_cat`, `not_visible`, `multiple_cats`;
- удаление отдельного прохода и его каталога после подтверждения;
- защита путей медиа от выхода за корневой каталог данных;
- тестовый режим без управления реальной дверью.

Текущий MVP запускает FFmpeg из веб-процесса. Следующий эксплуатационный этап —
перенос записи и RTSP-соединений в независимый `CatDoorRecorder`.

### 4. Инфраструктура обучения

- JSONL-манифест кадров с `event_id`, временем, ракурсом, меткой и split;
- проверка структуры, файлов и утечек событий между split;
- детерминированное разбиение 70/15/15 по событиям;
- локальное обучение MobileNetV3 на MacBook/MPS без автоматической загрузки
  pretrained-весов;
- экспорт модели в ONNX через современный exporter PyTorch;
- ZIP-пакет модели с `model_info.json`, `thresholds.json` и SHA-256;
- проверка целостности и защита пакета от path traversal;
- приёмка на Windows через ONNX Runtime CPU;
- отчёт по accuracy, FAR, FRR, uncertain rate и средней задержке;
- успешная приёмка не активирует модель автоматически.

### 5. Выбор данных и экспериментальное обучение на Windows

- в SQLite добавлено поле `training_target` через миграцию
  `003_training_target.sql`;
- для каждого размеченного прохода в админке можно выбрать `excluded`,
  `macbook` или `local`;
- для обучения допускаются только подтверждённые события `known_cat` и
  `foreign_cat`;
- добавлена подготовка до трёх кадров каждого доступного ракурса через FFmpeg;
- кадры центральной камеры при подготовке датасета физически поворачиваются на
  180°, исходное видео при этом не изменяется;
- split назначается по целому `event_id`, поэтому кадры одного прохода не
  попадают в разные выборки;
- из админки можно скачать ZIP с `dataset.jsonl`, отчётом и кадрами, выбранными
  для MacBook;
- короткое локальное CPU-обучение запускается отдельным Python-процессом и
  продолжает работу независимо от веб-интерфейса;
- статус, логи, подготовленные кадры и checkpoints локального запуска
  сохраняются только в каталоге данных и исключены из Git;
- установлен Microsoft Visual C++ Redistributable;
- в `.venv` установлены CPU-сборки PyTorch 2.13.0 и torchvision 0.28.0, импорт
  PyTorch успешно проверен;
- подготовлен отдельный промт для Codex на MacBook:
  `docs/codex-macbook-training-prompt.md`.

Фактическое обучение пока не запускалось: на момент проверки рабочая база
содержала 0 событий. Для классификатора требуются размеченные независимые
проходы минимум двух домашних котов и непустые train/validation split.

### 6. Восстановление конфигурации камер

- после перезапуска админка сообщила, что камеры не настроены;
- диагностика без вывода секретов показала, что веб-сервер не был запущен, а
  значение центрального RTSP-потока в локальном `.env` было пустым;
- центральный RTSP URL восстановлен только в локальном `.env`;
- обнаружено, что значение `CATDOOR_FFMPEG_PATH=ffmpeg` не работает для
  фонового процесса, потому что каталог WinGet отсутствует в его `PATH`;
- в локальном `.env` сохранён абсолютный путь к установленному `ffmpeg.exe`;
- веб-сервер перезапущен и отвечает HTTP 200;
- получение одного кадра через FFmpeg отдельно проверено для ролей `face` и
  `side`, оба RTSP-потока работают;
- секреты, RTSP URL и локальные пути установки не добавлялись в Git.
