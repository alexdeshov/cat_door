# История рабочей сессии — 2026-07-27

## Цель сессии

Подготовить первый локальный прототип CatDoor AI для двух камер, ручной записи и
разметки проходов, а также создать основу локального обучения и независимой
приёмки ONNX-моделей.

## Выполненные этапы

### 1. Подготовка Windows

- установлен Git for Windows;
- установлен FFmpeg/ffprobe;
- создано виртуальное окружение Python 3.13;
- установлены runtime- и dev-зависимости проекта;
- установлен и авторизован GitHub CLI.

### 2. Проверка камер

- проверена Ivideon V Ursa Minor через локальный RTSP;
- проверены основной и дополнительный H.264-потоки;
- обнаружена и проверена Ivideon Cute 2 в локальной Wi-Fi-сети;
- подтверждены основной и дополнительный H.264-потоки Cute 2;
- пароли и полные RTSP URL сохранены только в локальном `.env`.

Итоговые роли:

- центральная камера (`face`) — Ivideon Cute 2;
- дополнительная камера (`side`) — Ivideon V Ursa Minor;
- центральное изображение развёрнуто на 180° только в веб-интерфейсе.

### 3. Локальная админка MVP

- FastAPI application factory;
- MJPEG-превью обеих камер через локальные процессы FFmpeg;
- параллельная запись `face.mp4` и `side.mp4`;
- SQLite-модель событий и последовательные SQL-миграции;
- журнал событий и воспроизведение двух роликов;
- ручная разметка `known_cat`, `foreign_cat`, `not_visible`, `multiple_cats`;
- удаление отдельного прохода и его каталога после подтверждения;
- защита путей медиа от выхода за корневой каталог данных;
- тестовый режим без управления реальной дверью.

Текущий MVP запускает FFmpeg из веб-процесса. Следующий эксплуатационный этап —
перенос записи и RTSP-соединений в независимый `CatDoorRecorder`.

### 4. Инфраструктура обучения

- JSONL-манифест кадров с `event_id`, временем, ракурсом, меткой и split;
- проверка структуры, файлов и утечек событий между split;
- детерминированное разбиение 70/15/15 по событиям;
- локальное обучение MobileNetV3 на MacBook/MPS без автоматической загрузки
  pretrained-весов;
- экспорт модели в ONNX через современный exporter PyTorch;
- ZIP-пакет модели с `model_info.json`, `thresholds.json` и SHA-256;
- проверка целостности и защита пакета от path traversal;
- приёмка на Windows через ONNX Runtime CPU;
- отчёт по accuracy, FAR, FRR, uncertain rate и средней задержке;
- успешная приёмка не активирует модель автоматически.

## Проверки

- 17 автоматических тестов;
- Ruff без ошибок;
- mypy для runtime- и training-кода без ошибок;
- реальное превью обеих камер;
- параллельная тестовая запись обеих камер со статусом `ready`;
- секреты, реальные видео, SQLite и датасет исключены из Git.

## Текущее состояние

- рабочая ветка: `feature/local-event-admin`;
- локальная админка доступна только на loopback-интерфейсе;
- реальная дверь и контроллер не подключены;
- все решения остаются полностью локальными.
