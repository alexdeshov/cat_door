# История рабочей сессии — 2026-07-29

## Цель сессии

Перейти от ручной записи к полностью локальному автоматическому обнаружению
любой кошки и сохранению проходов двух камер для последующей разметки и обучения.

## Интерфейс камер

- центральное превью занимает основную широкую колонку;
- потоки можно менять местами без изменения ролей записи `face` и `side`;
- расположение сохраняется в браузере;
- для каждой физической камеры добавлен независимый поворот live-превью с шагом
  90 градусов;
- изображения обеих физически перевёрнутых камер поворачиваются на 180 градусов
  при отображении, инференсе и подготовке датасета;
- исправлено повторное открытие Cute 2 при первой загрузке страницы.

## Локальная детекция

- установлен OpenVINO 2026.2 для CPU/GPU Intel;
- подготовлен локальный ONNX-детектор SSDLite320 MobileNetV3 Large с весами COCO;
- модель проверяется по SHA-256 и хранится только локально в исключённом из Git
  каталоге `models/`;
- кадры обеих камер обрабатываются примерно с частотой 3 FPS;
- реализован автомат `idle → candidate → active → tail → cooldown`;
- событие подтверждается по серии кадров, а не по одиночной детекции;
- подтверждения могут поступать последовательно с разных камер;
- админка раз в секунду показывает состояние, confidence, число кадров и
  актуальность heartbeat.

## Независимые процессы

- добавлены отделённые процессы `CatDoorWeb` и `CatDoorRecorder`;
- web и recorder продолжают работу независимо от окна запуска;
- локальные stdout/stderr сохраняются в каталоге runtime и не попадают в Git;
- исправлен конфликт Windows при одновременном чтении и атомарной записи
  heartbeat;
- heartbeat ограничен двумя обновлениями в секунду и использует повторные
  попытки при кратковременной блокировке файла.

## Кольцевой буфер и автоматические события

- FFmpeg одним подключением к каждой камере одновременно выдаёт кадры детектору
  и создаёт короткие MP4-сегменты;
- буфер хранит последние 180 секунд и удаляет более старые временные сегменты;
- событие включает 12 секунд предыстории, подтверждённое присутствие кошки и
  хвост после её исчезновения;
- сегменты обеих камер объединяются без повторного кодирования;
- в SQLite добавлены источник события, камера-инициатор и максимальные
  уверенности `face`/`side`;
- автоматические события помечаются в журнале отдельно от ручных;
- при сбое одной камеры событие сохраняется как `partial`;
- управление дверью и контроллером отсутствует.

## Аппаратные проверки

- обе реальные камеры стабильно обрабатываются параллельно;
- ограниченный dry-run обработал 57 кадров `face` и 58 кадров `side` за 20 секунд;
- smoke-тест кольцевого буфера собрал два ненулевых MP4 из последних 12 секунд;
- `face.mp4`: 6 сегментов, около 7,2 МБ;
- `side.mp4`: 7 сегментов, около 3,2 МБ;
- после smoke-теста включено автоматическое локальное сохранение подтверждённых
  событий;
- web отвечает HTTP 200, recorder heartbeat актуален.

## Проверки кода

- Ruff без ошибок;
- mypy без ошибок;
- `git diff --check` без ошибок.

## Безопасность

- облачный инференс не используется;
- RTSP URL, пароли и токены не добавлялись в Git или логи;
- ONNX, веса, видео, SQLite, временные сегменты и полный датасет исключены из Git;
- реальная дверь не управляется;
- силовая механика и ESP32/Arduino не затрагивались.

## Продолжение: идентификация котов и отчёты

- добавлена массовая разметка нескольких проходов как одного домашнего кота;
- размеченные группы направляются в офлайн-датасет для MacBook M5;
- добавлен локальный OpenVINO-классификатор личности для моделей `face` и `side`;
- при достаточной уверенности recorder публикует имя кота, иначе статус
  `неизвестный кот`;
- пути ONNX-моделей и порог идентификации задаются только через конфигурацию;
- блок автоматического сбора перенесён в начало страницы;
- в верхнюю сводку добавлены общие, автоматические, неразмеченные, домашние,
  чужие и ошибочные проходы, а также известные имена;
- добавлен отдельный отчёт обучения: число независимых проходов, распределение
  по котам и ракурсам, эпоха, loss, validation accuracy и предупреждения;
- малый датасет допускается только для проверки pipeline и явно помечается как
  непригодный для эксплуатации;
- веб-интерфейс перезапущен и проверен через HTTP 200;
- итоговая проверка: 50 тестов, Ruff и mypy без ошибок.

Модели, датасет, видео, база и секреты по-прежнему остаются только локальными и
не включаются в Git. Управление реальной дверью не добавлялось.
## Продолжение: эксплуатационный runtime, диагностика и настройка детекции

### Автозапуск и устойчивость Windows runtime

- В автозагрузку пользователя Windows добавлены веб-интерфейс, рекордер в режиме реальной записи и открытие админки в Chrome.
- Пока рекордер работает, процесс запрещает Windows переходить в сон. При штатной остановке ограничение снимается.
- Веб-интерфейс и рекордер остаются отдельными процессами: падение или перезапуск админки не должен останавливать запись и инференс.
- Управление реальной дверью не включалось; система по-прежнему работает без силовой механики.

### Ошибки, причины и исправления

- Задержка Wi-Fi-камер оказалась следствием лишних RTSP-подключений: каждая открытая админка создавала дополнительные FFmpeg-процессы, и суммарно их становилось шесть. RTSP оставлен только рекордеру, а веб-интерфейс теперь показывает локально опубликованные JPEG-кадры. В нормальном режиме остаются два FFmpeg-процесса — по одному на камеру.
- Отказ heartbeat на Windows был связан с конфликтом при замене общего временного файла `recorder-status.tmp`. Для публикации состояния используются уникальные временные файлы и повтор операции при кратковременной блокировке.
- Ошибка соединения с `127.0.0.1` возникала после внешнего завершения процесса веб-сервера, а не из-за маршрута приложения. Независимый скрытый запуск процесса устранил эту зависимость.
- Сообщение «запись была бы» без видео означало включённый dry-run. После проверки захвата режим реальной записи был включён и учтён в автозагрузке.
- Вертикальное сжатие появилось из-за прямого масштабирования кадра в `320x320`. Для инференса добавлено сохранение пропорций с полями.
- Чёрные полосы в админке были полями детекторного кадра. Веб-превью теперь получает кадр без этих полей.
- Разрешение веб-превью увеличено до `640x360`, при этом вход модели оставлен `320x320`, чтобы не ухудшать скорость инференса.
- Иногда Cute 2 появлялась только после второго обновления страницы из-за повторного использования браузером того же MJPEG URL. Добавлены уникальный параметр URL при загрузке страницы и заголовки, запрещающие кеширование и буферизацию.

### Детекция и быстродействие

- Очередь кадров ограничена двумя элементами; при переполнении удаляется самый старый кадр. Это не даёт задержке накапливаться.
- В рабочем замере медианное время инференса составило около 49 мс, возраст кадра — около 50 мс, максимальный наблюдавшийся возраст — 182 мс.
- Более поздние и редкие рамки Cute 2 не были вызваны общей производительностью конвейера: обе камеры обработали одинаковое число кадров. У узкоугольной Cute 2 кошка меньше времени находится в кадре, а ракурс сверху даёт модели более низкую уверенность.
- В сравнительном журнале Cute 2 имела максимум уверенности `0.8643`, но только 60 кадров с уверенностью не ниже `0.20` и 15 кадров не ниже `0.55`. У широкоугольной камеры было соответственно 385 и 227 кадров.
- Для каждой камеры введён независимый счётчик подтверждений. Подтверждённые сигналы передаются в общий автомат событий, поэтому наблюдения одной камеры не подменяют последовательность другой.

### Настройки и диагностика

- Настройки детекции вынесены в отдельный блок админки и сохраняются локально в runtime-каталоге, а не в Git.
- Профили камер разделены. Начальные значения:
  - Cute 2: порог события `0.30`, порог отображения рамки `0.15`, 2 подтверждения в окне из 5 кадров;
  - широкоугольная камера: порог события `0.55`, порог отображения рамки `0.20`, 2 подтверждения в окне из 5 кадров.
- Общими оставлены временные параметры автомата событий: тайм-аут кандидата 3 с, подтверждение отсутствия 3 с, хвост записи 10 с и пауза между событиями 5 с.
- Добавлен ротационный JSONL-журнал `C:\CatDoorData\runtime\detection.jsonl` размером до 10 МБ с пятью резервными файлами. В нём сохраняются наблюдения модели, уверенность, пороги, состояния и действия автомата, время инференса, возраст кадра, публикации и ошибки.
- На превью отображаются рамки и уверенность модели: зелёная рамка означает достижение порога события, оранжевая — только порога отображения.

## Продолжение: проигрывание сохранённых событий

- Встроенная панель браузерного `<video>` оказывалась сверху, потому что CSS-поворот
  на 180 градусов применялся ко всему элементу вместе с его нативными controls.
- Нативные controls заменены внешней панелью под изображением: воспроизведение и
  пауза, шкала времени, текущая позиция с длительностью и полноэкранный режим.
- Проверка кадров реального события подтвердила, что файлы не перепутывались:
  `face.mp4` содержит Cute 2, а `side.mp4` — Ursa Minor.
- Видимое несоответствие ролей возникало после перестановки live-камер в браузере:
  live-превью учитывало сохранённый порядок, а список событий всегда показывал
  `face` первым. Порядок и подписи записей теперь синхронизируются с выбранным
  расположением камер и содержат точные названия физических камер.
- Поворот записей раньше был одинаковым для обеих камер. Теперь к каждому ролику
  применяется индивидуальная настройка поворота соответствующей live-камеры,
  поэтому дополнительная камера не отображается вверх ногами.
- Исправления относятся только к отображению в админке: исходные MP4 не
  перекодируются и роли кольцевых буферов не меняются.
