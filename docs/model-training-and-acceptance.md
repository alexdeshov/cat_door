# Обучение и приёмка модели

## Граница доверия

MacBook формирует пакет модели, но не определяет окончательно, пригоден ли он
для целевой машины. Приёмка повторно проверяет SHA-256 и выполняет инференс на
отложенном наборе через ONNX Runtime CPU — на узле либо на самом MacBook. Отчёт приёмки не активирует модель автоматически.

```text
размеченные события
       ↓
manifest.jsonl → проверка утечек событий → train/validation/test
       ↓
PyTorch/MPS на Mac → checkpoint → ONNX
       ↓
model_info + thresholds + SHA-256 → ZIP
       ↓
офлайн-перенос
       ↓
проверка ZIP → ONNX Runtime CPU → FAR/FRR/latency report
```

## Контракты

### Датасет

Обязательные поля строки JSONL:

- `event_id`;
- `captured_at` в ISO 8601;
- `view`: `face` или `side`;
- относительный `image_path`;
- `label`, где `__foreign__` обозначает чужую кошку;
- `split`: `train`, `validation`, `test` или `null`.

Разбиение выполняется по `event_id`, поэтому соседние кадры одного прохода не
могут оказаться в разных частях.

Каждый `image_path` указывает на кроп самой уверенной рамки кошки, расширенный
на 20% с каждой стороны. Подготовку набора выполняет локальный детектор
узла; кадры без рамки выше порога камеры не включаются и подсчитываются в
`dataset-report.json`.

### Пакет

Минимальный пакет содержит:

- один или несколько файлов `*.onnx`;
- `model_info.json`;
- `thresholds.json`;
- `checksums.sha256`.

ZIP разрешает только файлы верхнего уровня. Абсолютные пути и `..` отклоняются.
Пакет собирается без повторного сжатия ONNX, чтобы уменьшить лишнюю нагрузку.

### Приёмочный отчёт

Отчёт содержит:

- число домашних и чужих примеров;
- accuracy;
- False Accept Rate;
- False Reject Rate;
- долю `uncertain`;
- среднее время инференса;
- результат проверки лимита средней задержки на целевой машине;
- итог `passed`;
- неизменяемое поле `activated: false`.

Отсутствие домашних или чужих примеров всегда означает провал приёмки.
Превышение `max_mean_inference_ms` также означает провал.

Расчёт выполняется общим чистым модулем `src/common/metrics.py`, который
используют приёмка, recorder и офлайн-оценка. Ошибочное имя домашнего кота
считается одновременно false reject и отдельным `misidentified_known`.
Состояния `uncertain` и `no_prediction` не объединяются. Если в срезе нет
домашних либо чужих событий, соответствующая ставка FRR/FAR имеет значение
`null`, а отчёт считается непригодным — нулём отсутствие примеров не
подменяется. Threshold sweep повторно применяет сетку порогов к сохранённым
сырым confidence без нового инференса.

## Офлайн-оценка сохранённых событий

Админка запускает replay отдельным процессом через `POST /api/evaluations`.
Запуск фиксируется в `evaluation_runs`, а решения по каждому событию и ракурсу
— в `event_predictions` с `origin=evaluation`. Процесс выполняет события
строго последовательно и использует OpenVINO CPU, чтобы не конкурировать с
recorder несколькими параллельными инференсами. Временные JPEG удаляются сразу
после обработки события.

Фильтр запуска сохраняет диапазон дат, ручные метки и назначение обучения.
Отчёт содержит FAR, FRR, `misidentified_known`, uncertain, confusion,
threshold sweep, время инференса и detection miss отдельно для камер. Рядом
с общей выборкой рассчитывается «чистый» срез без событий с
`training_target=macbook|local`; сравнивать версии следует прежде всего по
нему. Ночные события (локальное время до 07:00 или после 20:00) выводятся
отдельным срезом. Ни успешный запуск, ни его отчёт не активируют модель и не
изменяют пороги.

## Текущие ограничения

- рабочая схема с 2026-08-11 — **эмбеддинги** (MobileNetV3-Small с угловым
  зазором, вектор 128, эталоны в метаданных модели); closed-set классификатор
  остаётся запасной веткой;
- `__foreign__` в эмбеддингах участвует в обучении как сила, растаскивающая
  пространство, эталона не получает;
- порог выбирается по отложенному набору с защитой от маленькой выборки чужих
  (`src/common/prototypes.py`): один выброс границу не назначает;
- кадры с двумя котами в наборы не попадают (`excluded_two_cats`);
- fusion ракурсов и детектор именно морды — отдельными изменениями;
- OpenVINO benchmark и сравнение с ONNX Runtime не автоматизированы.
