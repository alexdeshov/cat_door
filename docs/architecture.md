# Архитектура

Исходный контекст — в `PROJECT_BRIEF.md`; фактическое состояние узла — в
`docs/session-history.md`.

## Компоненты (работают)

- `catdoor-recorder` — RTSP, кольцевой буфер, детекция котов, опознание по
  эталонам, запись проходов; автоматика дверцы принимает решение по живому
  кадру камеры дверцы (`src/recorder/cat_door_automation.py`).
- `catdoor-web` — локальная веб-админка и API; превью, разметка, инвентарь
  камер, страницы калитки, регистратора и состояния узла.
- `catdoor-gate-access` — журнал проходов калитки: опрашивает Frigate,
  принимает решение об открытии по лицу и единственная пишет на плату реле.
- `catdoor-gate-notify` — уведомления о проходах калитки в Телеграм.
- `catdoor-gate-sync` — примиритель: приводит Frigate к состоянию контуров узла.
- `catdoor-backup` (таймер, 05:35) — резервная копия на внешний диск; отчёт
  виден на странице «Состояние».
- Frigate и mosquitto (Docker, репозиторий `gate_access`) — контуры «Калитка» и
  «Регистратор»: люди, машины, распознавание лиц; брокер отдаёт состояние
  створки и события без опроса (`docs/mqtt-broker.md`).
- Плата реле Waveshare (Modbus TCP через шлюз) — единственная силовая механика:
  реле 1 — «кнопка выхода» калитки, реле 2 — защёлка дверцы, вход DI1 — геркон
  дверцы. Пишет на неё только `catdoor-gate-access`; остальные просят открытия
  файлом-просьбой (`src/common/gate_open_request.py`).
- `dnsmasq` и `chrony` — адреса и время для изолированной сети камер.

Инференс (детектор и идентификация) выполняется внутри recorder через
OpenVINO, отдельного процесса нет. Детектор с 2026-08-08 считает на встроенном
видеоядре (`CATDOOR_DETECTOR_DEVICE=GPU`), идентификация — на процессоре;
опознание — эмбеддинги с эталонами котов, эталоны пересчитываются на узле
кнопкой «Запомнить заново» и перечитываются recorder-ом без перезапуска.
Декодирование потоков камер — медиадвижком (VA-API; камеры регистратора — QSV).
Эталон рабочей конфигурации и способ её проверить —
`docs/reference-configuration.md`.

Отдельного сторожа нет: службы объявлены `Type=notify`, и зависший процесс
перезапускает systemd. Долгие работы (пересчёт эталонов, сборка набора)
живут отдельными процессами и переживают перезапуск админки
(`KillMode=process`).

Автоматический сбор событий использует конечный автомат внутри recorder:
`automatic-capture.md`. Контуры узла работают одновременно с 2026-08-05:
`two-circuits-plan.md`.

## Принцип отказоустойчивости

Каждый компонент имеет ограниченную ответственность. Падение веб-интерфейса не
останавливает запись, а сбой модели не приводит к небезопасному действию двери.
