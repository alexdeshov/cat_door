# Метрики и офлайн-оценка моделей

## Назначение

Контур метрик сравнивает версии моделей на одних и тех же локальных
размеченных событиях и показывает качество текущих online-предсказаний по мере
ручной разметки. Он не активирует модели, не меняет пороги и не управляет
дверью.

Минимальная единица оценки — событие (независимый проход), а не отдельный
кадр. Приоритет показателей:

1. False Accept Rate;
2. False Reject Rate;
3. доля `uncertain`;
4. задержка;
5. accuracy.

## Словарь решений

- `known:<имя>` — большинство кадров с этим именем достигло identity-порога;
- `uncertain` — модель запускалась, но ни одно устойчивое решение не достигло
  порога либо камеры назвали разных котов;
- `no_prediction` — identity не запускалась или не получила пригодный кроп.

Для одного ракурса имя выбирается большинством кадров выше порога. При равном
числе кадров побеждает имя с максимальным confidence. В объединённом online-
решении конфликт имён камер всегда даёт `uncertain`.

## Определения

Пусть:

- `K` — размеченные события `known_cat`;
- `F` — размеченные события `foreign_cat`;
- `FA` — события из `F` с решением `known:<любое имя>`;
- `FR` — события из `K` без решения `known:<правильное имя>`;
- `MI` — события из `K` с решением `known:<другое имя>`;
- `U` — решения `uncertain`;
- `N` — все оценённые события.

Формулы:

```text
FAR = FA / |F|
FRR = FR / |K|
uncertain_rate = U / N
accuracy = correct / N
```

`misidentified_known = MI` входит в `FR`, но показывается отдельно. Если
`|F| = 0`, FAR равен `null`; если `|K| = 0`, FRR равен `null`. Такой отчёт
непригоден для приёмки: отсутствие примеров нельзя считать нулевой ошибкой.

Detection miss для камеры — доля событий, где кот должен быть виден
(`known_cat`, `foreign_cat`, `multiple_cats` и выбранные неразмеченные
события), но максимальный detector confidence ни разу не достиг рабочего
порога этой камеры. `not_visible` в знаменатель не входит.

## Таблицы SQLite

Миграция `005_model_metrics.sql` добавляет:

### `model_versions`

- `kind`: `detector`, `identity_face` или `identity_side`;
- `file_name`: только имя локального файла, без секретных путей;
- `sha256`: уникальный идентификатор содержимого;
- `metadata_json`: manifest/model-info;
- `first_seen_at`.

Recorder и запуск оценки регистрируют модель идемпотентно по SHA-256.

### `event_predictions`

- ссылка на событие и версию модели;
- ракурс и источник `online`/`evaluation`;
- ссылка на evaluation run для replay;
- решение, имя, confidence и число использованных кадров;
- максимальный detector confidence и средняя задержка;
- сырые пары `(имя, confidence)` для threshold sweep.

В таблицу не записываются изображения, RTSP URL и пароли.

### `evaluation_runs`

- время создания/завершения, тип и статус;
- неизменяемый JSON-фильтр событий;
- версии detector/face/side;
- итоговый metrics JSON либо краткая ошибка.

## Жизненный цикл replay

1. Владелец открывает `/metrics`, задаёт диапазон и модели из локального
   каталога `models/`.
2. Web создаёт `evaluation_runs` со статусом `starting` и запускает отдельный
   detached-процесс.
3. Процесс принудительно использует OpenVINO CPU и обрабатывает по одному
   событию за раз.
4. FFmpeg извлекает до трёх кадров каждого ракурса; detector и identity
   используют тот же preprocessing, что recorder.
5. Временные JPEG удаляются после события. Предсказания сохраняются в SQLite.
6. Итоговый отчёт содержит общие, чистые и ночные срезы, confusion,
   threshold sweep, latency и detection miss.
7. Страница запуска показывает результат; два завершённых запуска можно
   сравнить на `/metrics/compare`.

Статус и лог процесса находятся только локально в
`CatDoorData/evaluations/<run-id>/` и не попадают в Git.

## Чистые события

Событие считается видевшимся в обучении, если его `training_target` равен
`macbook` или `local`. Основное сравнение версий выполняется по
`clean_metrics`, куда входят только события с `training_target=excluded`.
Общие метрики полезны для диагностики, но не доказывают обобщающую способность
модели.

Ночной срез определяется по локальному времени события: до 07:00 либо после
20:00. Это вспомогательное правило; в будущем его стоит заменить явной
меткой режима камеры.

## Скользящие online-метрики

`GET /api/metrics/online` пересчитывает 7 дней, 30 дней и весь период при
запросе. Объёмы локальной SQLite невелики, поэтому кеш не нужен. Для каждого
ракурса берётся последняя версия модели, встреченная в online-предсказаниях.
Показываются FAR, FRR, ошибочные имена, uncertain, число неразмеченных событий
и прогресс по домашним котам.

Кадры в прогрессе — фактически использованные identity-кадры из online-
предсказаний, а не размер экспортированного датасета.

## Threshold sweep

Сетка 0.50–0.95 с шагом 0.05 применяется к сохранённым сырым confidence без
повторного инференса. Она помогает предложить порог, но не изменяет runtime-
настройки. Новый порог активируется только отдельным ручным действием владельца
после анализа FAR на достаточном корпусе чужих котов.
