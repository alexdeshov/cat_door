# Руководство владельца узла CatDoor

Практическая шпаргалка: как зайти, что посмотреть, что делать, когда что-то
пошло не так. Технические обоснования решений — в остальных файлах `docs/`,
здесь только действия.

Настоящие адреса, логины и пароли в этом файле намеренно заменены на
placeholders: он лежит в репозитории. Впишите свои значения один раз в таблицу
ниже — на печатной копии от руки.

| Пул DHCP для камер | `192.168.1.180 – 192.168.1.240` |

## 1. Из чего состоит узел

Мини-PC (hostname `acer`) держит несколько служб:

| Служба | Что делает | Падение означает |
| --- | --- | --- |
| `catdoor-recorder` | смотрит в камеры, ищет и опознаёт котов, пишет проходы, решает про дверцу | сбор остановлен, автоматика дверцы молчит |
| `catdoor-web` | админка на порту 8080 | не видно интерфейса; запись при этом идёт |
| `catdoor-gate-access` | журнал проходов калитки, открытие по лицу, единственный доступ к плате реле | калитка не открывается ни по лицу, ни кнопкой; журнал не пополняется |
| `catdoor-gate-notify` | уведомления о проходах калитки в Телеграм | сообщений нет, всё остальное работает |
| `catdoor-gate-sync` | приводит Frigate к выбранным контурам узла | переключатель контуров перестаёт действовать |
| `catdoor-backup` (таймер) | ночная копия на внешний диск в 05:35 | видно на странице «Состояние» — копия стареет |
| `frigate` + `mosquitto` (Docker) | контуры «Калитка» и «Регистратор»: люди, машины, лица; брокер отдаёт состояние створки | их события и записи не появляются; состояние створки неизвестно |
| `dnsmasq` | выдаёт адреса камерам в изолированной сети | новые камеры не получат адрес |
| `chrony` | раздаёт камерам время | часы камер поплывут, штампы наврут |

Все контуры работают **одновременно** (с 2026-08-05). Переключатель в шапке
админки остаётся: им можно выключить любой контур, применяет примиритель в
течение двух минут.

Службы CatDoor подняты через systemd, перезапускаются сами и стартуют после
включения питания без участия человека. Веб-интерфейс намеренно отделён от
записи: перезапуск админки не прерывает ни сбор, ни пересчёт эталонов.

**Механика управляется в двух местах, и оба под правилами.** Калитка
открывается по узнанному лицу (режим включает владелец на странице «Калитка»),
защёлка дверцы — кнопкой на главной и автоматикой по опознанному коту (режим —
там же, на панели дверцы). Все команды идут через плату реле Waveshare, пишет
на неё только служба `catdoor-gate-access`, каждое срабатывание попадает в
журнал и в Телеграм.

### Где что лежит

| Путь | Содержимое |
| --- | --- |
| `/opt/catdoor` | код и виртуальное окружение |
| `/etc/catdoor/catdoor.env` | конфигурация служб, читает только root и `catdoor` |
| `/var/lib/catdoor/` | база, видео, модели, runtime-файлы |
| `/opt/catdoor/models/` | модель детектора котов и её manifest |
| `/var/lib/frigate/` | конфигурация и архив Frigate (пишет примиритель) |
| `/var/lib/catdoor/runtime/cameras.json` | инвентарь камер, **содержит пароли** |
| `/var/lib/catdoor/runtime/capture-mode.json` | положение переключателя сбора |
| `/var/lib/catdoor/runtime/gate-access.json` | настройки открытия калитки по лицу и оба пресета |
| `/var/lib/catdoor/runtime/cat-door.json` | настройки защёлки дверцы и её автоматики |
| `/var/lib/catdoor/runtime/backup-status.json` | отчёт последней резервной копии |
| `/var/lib/catdoor/runtime/detection.jsonl` | журнал происшествий: обрывы, переезды камер, проходы |
| `/var/lib/catdoor/runtime/observations.jsonl` | покадровые наблюдения детектора, живут часы |
| `/etc/dnsmasq.d/` | настройка DHCP для камер |

Каталог `/var/lib/catdoor` принадлежит служебному пользователю `catdoor`,
поэтому смотреть его содержимое нужно через `sudo`.

## 2. Вход на сервер

```sh
ssh <логин>@<адрес-мини-PC>
```

Дальше всё выполняется на сервере. Команды с `sudo` спросят пароль вашего
пользователя, а не root.

## 3. Ежедневная работа: админка

Откройте `http://<адрес-мини-PC>:8080`. Вкладки: «Проходы», «Камеры»,
«Метрики», «Состояние» и по одной на контуры Frigate — «Калитка 1» и
«Регистратор».

На «Проходах», кроме списка и разметки, живут панели «Дверца» (тестовое
открытие защёлки, автоматика по коту, список своих котов) и «Память о котах»
(пересчёт эталонов на узле и сборка набора для макбука). На «Калитке 1» —
журнал проходов людей, настройки открытия по лицу и два пресета с откатом.
«Состояние» сверяет узел с эталоном: детектор, калитка, железо, резервная
копия.

### Проходы

Главная страница. Сверху строка состояния: точка, одно слово о том, что делает
детектор, и показания по камерам. Справа переключатель сбора на три положения:

- **выключен** — детектор не запускается;
- **наблюдение** — детектор работает и всё показывает, но на диск ничего не
  пишет;
- **запись** — подтверждённые проходы сохраняются.

Переключение применяется в течение секунды, но только когда система не
записывает проход прямо сейчас. Перезапускать службы не нужно.

Ниже счётчики, живое изображение камер и список проходов. Разметка прохода —
одно нажатие по переключателю «свой / чужой / кота не видно / несколько»,
сохраняется сразу. Ошиблись — нажмите соседнюю кнопку. Для своего кота
появляется поле имени, оно подсказывает уже известные имена.

Кнопка «Записать проход сейчас» сохраняет короткий ролик немедленно, не дожидаясь
детектора. Так набирают первые кадры, пока автоматика выключена.

### Камеры

Список камер, их адреса, роли и настройки детекции.

Роли `face` (идентификация) и `side` (подход) принадлежат сцене, а не железу. На
них завязаны детектор, таблицы событий и модели по ракурсам. Переставили камеры
местами — смените роль в карточке или нажмите «Поменять роли местами»; адреса
трогать не нужно. Настройки детекции остаются за ролью и продолжают описывать ту
же точку съёмки.

Кнопка «Проверить поток» забирает с камеры один кадр и показывает причину
отказа. В браузере неверный пароль, несуществующий путь и молчащая камера
выглядят одинаково — пустым прямоугольником, поэтому проверяйте кнопкой.

### Метрики

Онлайн-показатели по размеченным проходам, статистика детекции по камерам,
прогресс датасета и запуски офлайн-оценки.

## 4. Камеры

### Найти новую камеру

Вкладка «Камеры» → «Поиск камер» → логин и пароль камеры → «Найти камеры».
Опрашиваются аренды DHCP, ARP-таблица, ONVIF и, если задана подсеть, RTSP-порт
каждого адреса. Найденное сопоставляется с инвентарём по MAC, поэтому
переставленная камера показывается как известная с новым адресом, а не как
новая.

Ничего не применяется само: кнопка в строке результата подставляет адрес и путь
потока в карточку, сохраняет обычная кнопка «Сохранить».

### Зайти в вебморду камеры

Камеры в изолированной сети и напрямую с мака недоступны. Поднимите туннель —
команда держит сессию открытой, пока вы настраиваете:

```sh
ssh -L 8081:<адрес-камеры>:80 <логин>@<адрес-мини-PC>
```

Теперь камера доступна на `http://localhost:8081`. Закончив, закройте сессию
`Ctrl+D`. Если порт 80 закрыт, поищите вебморду на 8000, 8080, 8899 или 34567:

```sh
for p in 80 8000 8080 8899 34567; do
  timeout 1 bash -c "exec 3<>/dev/tcp/<адрес-камеры>/$p" 2>/dev/null && echo "$p открыт"
done
```

### Что настроить в новой камере

1. **Пароль администратора** — до этого RTSP не отдаст поток.
2. **Статический адрес** — вне пула, не равный заводскому, со шлюзом
   `192.168.1.10` обязательно. Полный порядок из шести правил — в
   `docs/cameras.md`, «Порядок подключения новой камеры».
3. **NTP на узел** — сервер времени `192.168.1.10`; команды для обеих платформ
   там же, пункт 5. Иначе камера живёт в 1970 году и вжигает это в кадры.

### Посмотреть, кто в сети

```sh
sudo cat /var/lib/misc/dnsmasq.leases
```

Каждая строка: срок, MAC, адрес, имя. Так находится камера, у которой нет ни
экрана, ни известного адреса.

### Закрепить адрес за камерой

Адрес из пула достаётся тому, кто первым его попросит. Чтобы он не гулял:

```sh
sudo tee -a /etc/dnsmasq.d/catdoor-cameras-local.conf > /dev/null <<'EOF'
dhcp-host=<MAC камеры>,<адрес>
EOF
sudo systemctl restart dnsmasq
```

Зарезервированный адрес dnsmasq больше никому не предложит.

## 5. Состояние и журналы

```sh
systemctl status catdoor-recorder --no-pager
systemctl status catdoor-web --no-pager
journalctl -u catdoor-recorder -n 50 --no-pager
sudo tail -20 /var/lib/catdoor/runtime/detection.jsonl
sudo cat /var/lib/catdoor/runtime/recorder-status.json
```

Журналов два, и путать их не стоит. В `detection.jsonl` попадают редкие
события — их стоит знать пять:

| Событие | Что означает |
| --- | --- |
| `stream_starving` | камера молчит дольше `CATDOOR_CAMERA_STALL_SECONDS` |
| `stream_stalled` | камера замолчала, поток перезапущен |
| `stream_recovered` | кадры пошли снова |
| `camera_address_recovered` | камера найдена по MAC на новом адресе, адрес подставлен |
| `event_published` | проход сохранён в базу |

В `observations.jsonl` — по строке на каждый разобранный кадр: уверенность,
порог, состояние автомата. По ним считается статистика на странице метрик, и
живут они часы, а не дни: при 10 кадрах в секунду файл ротируется примерно раз
в полчаса. Раньше обе породы событий лежали вместе, и покадровые вытесняли
происшествия быстрее, чем до них доходили руки.

## 6. Обновление

```sh
cd /opt/catdoor
git pull
.venv/bin/pip install -e '.[dev,inference]'
.venv/bin/pytest -q
sudo ./install/install.sh          # только если менялись файлы в install/
sudo systemctl restart catdoor-web catdoor-recorder
```

`install.sh` намеренно не перезапускает службы сам: обновление не должно
оборвать запись в середине прохода. Перезапуск — отдельной строкой и в удобный
момент.

**Перезапускать нужно обе службы, а не только веб.** Они делят файлы состояния —
инвентарь камер, режим сбора, состояние узла, — и служба, оставшаяся на старом
коде, встречает в них значения, которых её версия не знает. 4 августа это
стоило всего инвентаря камер: recorder не был перезапущен, увидел камеру в
контуре «Регистратор», которого его версия ещё не знала, счёл файл испорченным
и заменил умолчаниями из `.env`. Незнакомые значения с тех пор обнуляются по
полю и файл целиком не теряется, но расхождение версий всё равно означает, что
половина узла работает по старым правилам.

## 7. Если что-то пошло не так

| Симптом | Вероятная причина | Что сделать |
| --- | --- | --- |
| Админка не открывается | служба упала или порт закрыт | `systemctl status catdoor-web`, `sudo ufw status` |
| Строка состояния «Recorder молчит» | recorder не запущен или завис | `journalctl -u catdoor-recorder -n 50` |
| Превью чёрное | камера недоступна или неверный пароль | «Проверить поток» в карточке камеры |
| На превью «нет сигнала» со счётчиком | камера молчит: питание, сеть, адрес | дождаться — поток переоткрывается сам; если счётчик растёт минутами, проверить питание и `journalctl -u catdoor-recorder -n 50` |
| На превью нет рамок детекции | recorder не публикует кадры: перезапуск, загрузка моделей, сбор выключен | картинка идёт прямо с камеры; рамки вернутся сами, как только recorder заработает — `systemctl status catdoor-recorder` |
| Записи проходов вверх ногами | флаг «поворот на 180°» у камеры не совпадает с тем, как она висит | поправить флаг в карточке камеры на вкладке «Камеры» |
| Инвентарь камер сбросился к умолчаниям | файл сочли испорченным и пересоздали из `.env` | прежний лежит рядом: `sudo ls /var/lib/catdoor/runtime/cameras.json.invalid-*`; остановить recorder, вернуть файл на место, запустить обратно |
| Камера вдруг «не пускает по паролю» | другая камера перехватила её адрес | `ip neigh show dev eno1` — один MAC на двух адресах или чужой MAC; подробности в `docs/cameras.md`, «Столкновение адресов» |
| Камера пропала совсем: не пингуется, нет в арендах и в поиске | не удался DHCP, камера ушла в link-local `169.254.x.x` | не спешить считать мёртвой: `sudo ip addr add 169.254.1.1/16 dev eno1`, затем найти адрес захватом при включении — `docs/cameras.md`, «Камера пропала из сети» |
| Камера пропала из сети | сменила адрес | «Найти камеры», кнопка «Новый адрес» |
| Проходы не появляются | переключатель в «наблюдении» | перевести в «запись» |
| Детектор не запускается | нет модели или OpenVINO | `ls /opt/catdoor/models/` |
| Кончилось место | накопились видео | `df -h /var/lib/catdoor` |
| `dnsmasq` в `failed` после перезагрузки | стартовал раньше сети | `journalctl -u dnsmasq -b`, затем `sudo systemctl restart dnsmasq` |
| `dnsmasq` в `failed` после установки пакетов | `ubuntu-fan` добавил свой конфликтующий конфиг | `sudo apt-get -y purge ubuntu-fan` |

Служба, упавшая с ошибкой, перезапускается сама с нарастающей паузой от 5 секунд
до получаса и не сдаётся никогда. Если состояние «Перезапуск» держится, причина
в журнале.

## 8. Чего делать нельзя

- **Не коммитить в Git** пароли, RTSP-адреса, IP и MAC камер, видео и базу.
  Реквизиты этого узла живут только в `/etc/catdoor/catdoor.env`,
  `/var/lib/catdoor/runtime/cameras.json` и локальном файле dnsmasq.
- **Не открывать порт 8080 наружу.** В админке нет аутентификации: она удаляет
  события и показывает потоки с камер. Доступ ограничен домашней сетью правилом
  `ufw`.
- **Не выводить камеры в интернет.** Изолированная сеть — требование проекта, а
  не удобство.
- **Не менять `main` на сервере.** Обновление только `git pull`; правки идут
  через ветку и pull request с другой машины.
