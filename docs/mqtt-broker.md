# Брокер MQTT: зачем он и как его поднять

## Зачем

Frigate отдаёт по HTTP не всё. Три вещи приходят только в MQTT, и все три нам
нужны:

1. **Состояние калитки** от обученного классификатора («открыта» / «закрыта»).
   По HTTP его нет вовсе: `/api/classification/<модель>` отвечает 405 — маршрут
   существует только для управления набором и обучением. Это тот сигнал
   обратной связи, от которого отказались вместе с герконом: с ним «открыл» в
   журнале означает «калитка действительно открылась», а заклинивший замок
   перестаёт быть невидимым.
2. **Обновления трека по ходу прохода** (`tracked_object_update`) — рамка
   человека, пока он идёт. Отсюда берётся направление: приходящий растёт в
   кадре, уходящий тает. По HTTP конечная рамка появляется только когда проход
   закончился, а решать надо раньше.
3. **События лиц без задержки опроса** — так казалось при установке брокера.
   Замер 2026-08-12 показал обратное: между появлением имени в
   `tracked_object_update` и импульсом — одна секунда, опрос не отстаёт, вся
   задержка уходит на само распознавание. На подписку не переходим: выигрыш
   секунда, цена — второй источник имени и вопрос, какому верить при
   расхождении (`docs/gate-direction-experiments.md`).

## Где он живёт

**Соседним сервисом в том же `docker-compose.yml`, что и Frigate.** Причина
техническая: Frigate работает в контейнере с мостовой сетью, и `127.0.0.1`
внутри него — это он сам, а не узел. Брокер на узле он бы не увидел.

Отсюда два адреса одного брокера, и это не дублирование:

| кто подключается | адрес | настройка |
|---|---|---|
| Frigate, из контейнера | `mqtt:1883` — имя сервиса в compose | `CATDOOR_GATE_MQTT_HOST` |
| службы узла | `127.0.0.1:1883` — опубликованный порт | `CATDOOR_MQTT_HOST` |

Порт публикуется **только на loopback**: наружу брокер не смотрит, поэтому
авторизация не заводится. Если порт когда-нибудь понадобится в сети, пароли
становятся обязательными в тот же день.

## Что добавить в compose

Файл `docker-compose.yml` на узле лежит в `/opt/gate_access` и **не находится в
репозитории** — правится руками, рядом хранится `.bak`. Добавляется один сервис:

```yaml
  mqtt:
    container_name: catdoor-mqtt
    image: eclipse-mosquitto:2
    restart: unless-stopped
    volumes:
      - /etc/mosquitto/catdoor.conf:/mosquitto/config/mosquitto.conf:ro
    ports:
      # Только loopback: наружу брокер не смотрит.
      - "127.0.0.1:1883:1883"
```

и файл `/etc/mosquitto/catdoor.conf`:

```
listener 1883
allow_anonymous true
# Сохранять сообщения незачем: нас интересует происходящее сейчас, а не архив.
persistence false
```

## Порядок установки

Всё это делает `install/enable-mqtt.sh`, запускаемый на узле:

```
cd /opt/catdoor && git pull
sudo ./install/enable-mqtt.sh
```

Скрипт повторяемый: проверяет, что уже сделано, и дважды не делает. По шагам он
выполняет то же, что пришлось бы руками, и в том же порядке — брокер
поднимается **до** включения MQTT в конфигурации, иначе Frigate сыплет ошибками
подключения в лог.

1. Создаёт `/etc/mosquitto/catdoor.conf`.
2. Добавляет сервис `mqtt` в compose, сохранив прежний файл рядом с отметкой
   времени.
3. Поднимает **только** брокер (`up -d mqtt`) — Frigate при этом не
   перезапускается.
4. Проверяет, что брокер принимает подключения и что порт виден на loopback.
5. Ставит `CATDOOR_GATE_MQTT_ENABLED=true` и запускает примиритель, который
   пересобирает `config.yml`.
6. Показывает получившийся раздел `mqtt` и **спрашивает**, перезапускать ли
   Frigate: это перерыв в записи обоих контуров, и молча такое не делается.

Откат: `sudo ./install/enable-mqtt.sh --disable` вернёт `enabled: false`.
Контейнер брокера остаётся — он никому не мешает.

## Чего ждать от состояния калитки

Классификатор считает по картинке с камеры регистратора и срабатывает по
движению в заданном прямоугольнике. Значит:

- между движениями известно **последнее** состояние, а не текущее;
- ночь, дождь, снег на створке и заслонившая обзор машина сбивают его;
- модель обучена на нынешнем виде: подвинут камеру или отрастёт куст — потребуется
  дообучение, тем же циклом, что и у котов.

Поэтому состояние калитки годится как **свидетельство** для журнала и как один
из голосов в решении, но не как единственный судья.
