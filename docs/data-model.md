# Модель данных

Фактическая схема SQLite (`src/common/database.py`):

- `events` — проход кота: статус, метка разметки, имя кота, назначение для
  обучения, пути к видео обеих камер, уверенности детектора, какая камера
  начала событие;
- `model_versions` — версии моделей по SHA-256: детектор и identity-модели;
- `event_predictions` — предсказания identity по событиям, онлайн и офлайн;
- `evaluation_runs` — запуски офлайн-оценки для страницы метрик;
- `gate_passes` — журнал проходов калитки: кто, с какой уверенностью, решение и
  его причина, факторы, направление движения, состояние створки до и после,
  счётчик импульсов и состояние створки в момент импульса.

Схема меняется только миграциями `src/common/migrations/*.sql`; команды
исполняются по одной, точка с запятой в русском комментарии не режет команду
(выучено на миграции 014).

Видео лежит в файловой системе (`/var/lib/catdoor/events/`), в базе — метаданные
и пути. Снимки проходов калитки — `runtime/gate-passes/`.

Не в базе, а в runtime-файлах (`/var/lib/catdoor/runtime/`):

- `cameras.json` — инвентарь камер (**содержит пароли**);
- `detection-settings.json` — настройки детекции;
- `circuits.json`, `capture-mode.json` — состояние контуров и режим сбора;
- `gate-access.json` — настройки открытия калитки по лицу, включая оба пресета
  и их резервные копии;
- `cat-door.json` — настройки защёлки дверцы и её автоматики;
- `gate-open-request.json` / `gate-open-result.json` — просьба открыть и ответ:
  так админка и recorder просят службу калитки, единственную с правом писать
  на плату;
- `backup-status.json` — отчёт ночной резервной копии (пишет
  `scripts/backup_to_archive.sh`, читает страница «Состояние»);
- `detection.jsonl`, `observations.jsonl` — журналы происшествий и покадровых
  наблюдений.

Долгие работы оставляют состояние в `/var/lib/catdoor/training/`:
`prototypes/<прогон>/status.json` — пересчёт эталонов, `exports/<прогон>/` —
сборка набора для макбука (готовые архивы — в `exports/` каталога данных).
