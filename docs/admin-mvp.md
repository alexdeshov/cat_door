# Локальная админка MVP

## Назначение

MVP позволяет просматривать центральную камеру Cute 2 (роль `face`) и
дополнительную Ursa Minor (роль `side`), параллельно сохранять короткие проходы
и размечать их для будущего датасета.

Центральная камера повёрнута на 180° средствами веб-интерфейса. Поворот применяется
к живому превью и воспроизведению `face.mp4`, но не изменяет исходный RTSP-поток и
не перекодирует сохранённый файл.

Приложение не выполняет инференс и не отправляет команды двери.

## Данные

По умолчанию используются:

```text
data/
├── catdoor.sqlite3
└── events/
    └── 00000001/
        ├── face.mp4
        └── side.mp4
```

В SQLite сохраняются время, длительность, относительный путь к видео, статус и
ручная разметка. RTSP URL и пароль в базе не сохраняются.

Типы разметки:

- `pending`;
- `known_cat` с обязательным именем;
- `foreign_cat`;
- `not_visible`;
- `multiple_cats`.

Оператор может удалить отдельное ошибочное событие. После подтверждения удаляются
строка события в SQLite и только связанный каталог `events/NNNNNNNN` внутри
корневого каталога данных. Восстановление через интерфейс не предусмотрено.

## Ограничения

Это временный минимальный вариант для начала сбора данных:

- событие начинается после нажатия кнопки, предыстории пока нет;
- превью и короткая запись запускаются веб-процессом через отдельные процессы
  FFmpeg;
- история исправлений разметки и ZIP-экспорт ещё не реализованы.

До эксплуатационной версии запись будет перенесена в независимый
`CatDoorRecorder` с очередью SQLite и кольцевым буфером. Это необходимо, чтобы
перезапуск веб-интерфейса не прерывал запись.

## Безопасность

- приложение слушает только `127.0.0.1`, пока доступ из домашней сети отдельно не
  согласован;
- путь к видео формируется сервером и проверяется относительно каталога данных;
- незавершённый ролик публикуется только после успешного завершения FFmpeg;
- секреты задаются через локальный `.env`, который исключён из Git;
- реальная дверь и контроллер не используются.
