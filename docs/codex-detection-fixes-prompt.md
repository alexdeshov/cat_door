## Фаза 1. Баг: идентификация почти не запускается для Cute 2

В `src/recorder/app.py` в `monitor_automatic` гейт запуска identity-модели
использует глобальный порог из настроек:

    if confidence >= settings.detection_confidence_threshold and role in identity_models:

Для Cute 2 рабочий порог детекции специально снижен до 0.30 в пер-камерном
runtime-профиле (`src/common/detection_config.py`, админка), но гейт сравнивает
с глобальным 0.55, поэтому классификатор личности для `face` вызывается в разы
реже, а изменения порогов через админку на него не влияют.

Исправление: использовать действующий пер-камерный порог
`camera_config.confidence_threshold` (переменная уже вычислена выше в цикле).
Добавь тест, который проверяет, что identity вызывается при confidence между
пер-камерным и глобальным порогом для `face` и не вызывается ниже
пер-камерного.

## Фаза 2. Баг: рассинхрон препроцессинга identity между обучением и инференсом

Сейчас на инференсе (`src/recorder/app.py` -> `OpenVinoCatIdentity.predict`)
классификатор личности получает детекторный кадр 320x320 с чёрными
letterbox-полями (`prepare_detector_frame` в `src/recorder/frames.py`), а при
обучении (`training/workflow.py` -> `extract_frames`,
`training/train_classifier.py`) кадры извлекаются из MP4 в полном разрешении
без полей. Модель работает не на том распределении, на котором обучалась.

Кроме того, классификатор видит весь кадр, а не кота: рамка из
`CatDetectionResult` никак не используется, поэтому модель фактически учится
на фоне сцены.

Исправление (единый контракт для обучения и инференса):

- на инференсе выбирать наиболее уверенную рамку класса `cat`, расширять её на
  ~20% с каждой стороны, обрезать по границам кадра и передавать в identity
  кроп без letterbox-полей; пересчёт координат рамки из 320x320 в кадр без
  полей уже реализован в `annotate_detections` (`src/recorder/preview.py`) —
  вынеси его в общую функцию, не дублируй;
- при подготовке датасета прогонять извлечённые кадры через тот же детектор
  (модель `models/cat-detector.onnx` доступна локально на Windows) и сохранять
  такие же кропы; кадры без уверенной рамки помечать в отчёте датасета и не
  включать в манифест молча;
- зафиксируй контракт препроцессинга (кроп, расширение, resize, нормализация)
  в одном модуле и в документации, чтобы обучение и инференс не могли снова
  разойтись;
- предусмотри совместимость: если рамки нет (детектор не сработал, а identity
  вызвана), поведение должно быть явным и залогированным, без исключений.

## Фаза 3. Претрен для identity-классификатора

`training/train_classifier.py` создаёт `mobilenet_v3_small(weights=None)` —
обучение с нуля на сотнях кадров бессмысленно. Используй
`MobileNet_V3_Small_Weights.IMAGENET1K_V1` с дообучением. Требование офлайна
сохрани так: скачивание весов допустимо один раз на MacBook при подготовке
окружения; добавь флаг `--weights-path` для явного локального файла весов и
понятную ошибку, если весов нет и сети тоже нет. Веса в Git не добавлять.

Также убери `RandomHorizontalFlip` для идентификации: окрас кота асимметричен,
зеркальная аугментация смешивает левый и правый бока. Оставь/добавь безопасные
аугментации (яркость, контраст, небольшие повороты, RandomResizedCrop с
умеренным диапазоном).

## Фаза 4. Детектор: ROI и частота кадров для Cute 2

Не меняя модель детектора, подними качество входа:

- добавь пер-камерную настройку ROI (прямоугольник в относительных координатах
  0..1), применяемую в FFmpeg-фильтре `crop` до масштабирования в
  `rgb_frame_stream` (`src/recorder/frames.py`); для Cute 2 это позволит
  вырезать зону дверцы в нативном разрешении вместо letterbox всего кадра —
  кот станет крупнее для детектора; ROI задаётся через конфигурацию и админку,
  по умолчанию выключен; ring-буфер и записи событий должны по-прежнему
  сохранять полный кадр (ROI влияет только на ветку детектора);
- сделай `detector_sample_fps` пер-камерным: для `face` кот находится в
  полезной зоне доли секунды, нужно 6–8 FPS, для `side` достаточно текущих 3;
  учти, что очередь кадров ограничена двумя элементами — проверь, что кадры
  `side` не вытесняются полностью;
- рамки и превью должны корректно учитывать ROI (пересчёт координат).
