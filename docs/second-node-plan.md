Зафиксирован 2026-08-14 по итогам обсуждения с владельцем. Статус: **план,
работы не начаты.** Второй сервер существует (Ubuntu с подготовленной флешки,
сейчас в домашней сети), вторая калитка — у другого дома, с другим Wi-Fi.

## Сеть: три NAT и правило матрёшки

```
интернет ── роутер провайдера 192.168.0.1
                └── Keenetic Hero 4G 192.168.1.1
                        └── Xiaomi AX3000 192.168.2.1
                                └── узел acer 192.168.2.137 (Wi-Fi wlo1)
                                        └── сеть камер 192.168.1.0/24 (enp46s0, изолирована)
```

Правило: **изнутри наружу видно, снаружи внутрь — нет.** Проверено живыми
замерами 2026-08-14:

- с acer достижим 192.168.0.1 (сквозь оба NAT) — «вверх» ходить можно;
- 192.168.1.1 (Keenetic) с acer **недостижим навсегда**: его подсеть затенена
  собственной камерной сетью узла. Подсеть 192.168.1.0/24 для общих служб
  проклята — ничего там не размещать;
- ловушка на клиентах: VPN на макбуке заворачивал 192.168.0.0/24 в туннель
  (`route get` показывал utun), и роутер провайдера «не пинговался». На
  устройствах с VPN исключать домашние подсети из туннеля.

**Следствие:** второй сервер в сети 192.168.0.x — лучшее место для общих
служб: его видят все вложенные сети, а он сам не может инициировать связь
вглубь (и не должен).

## Что стоит на втором сервере

Контур «Калитка 2» по образцу первого: Frigate (лица) + управление второй
калиткой + **общий хаб**:

- **mosquitto** — события обоих узлов; acer подключается клиентом (направление
  «вглубь → вверх» разрешено, обратное — нет);
- **ntfy** — локальные push-уведомления: приложение на телефоне держит
  подписку сам (телефон → сервер, NAT-дружелюбно), оба узла публикуют. Дома
  уведомления ходят без интернета; вне дома остаётся Телеграм — обе трубы
  кормятся одними событиями;
- камеры второго узла — в изолированной подсети **192.168.3.0/24** (не
  192.168.1.0/24 — см. выше), тот же dnsmasq/chrony-набор, что на первом.

Безопасность: верхняя сеть — самая открытая (её видит весь дом, рядом
провайдерская коробка). ufw с первого дня, админка без аутентификации закрыта
от WAN так же строго, как на первом узле.

## Камера второй калитки и записи

Принцип автономии тот же, что у первой калитки: **распознавание и реле живут
рядом с калиткой** — вторая калитка работает, даже когда домашняя сеть лежит.
Отсюда:

- пишет второй сервер локально; на первый уезжают **события** (хаб),
  **архив по расписанию** (ночной rsync) и **живой просмотр по требованию**
  (рестрим go2rtc); в админке acer — вкладка «Калитка 2» по образцу
  «Регистратора»;
- прямая запись камеры-2 на Frigate acer возможна (камера в 0.x или рестрим),
  но постоянный поток пойдёт через два роутера — приемлемо только после
  провода (см. ниже), и всё равно вторично к локальной записи.

## Провод для acer вместо Wi-Fi

У узла есть свободный порт **enp45s0** (проверено 2026-08-14; enp46s0 занят
камерами). Кабель enp45s0 ↔ Xiaomi убирает главный известный риск узла —
Wi-Fi с историей обрывов (см. «Домашняя сеть узла») — и делает честной запись
второй камеры через дом.

Порядок без потери доступа:

1. воткнуть кабель; `sudo tee /etc/netplan/60-wired-home.yaml` с
   `enp45s0: {dhcp4: true}`; **`sudo netplan try`** (сам откатится за 120 с);
2. метрики всё решают сами: провод 100, Wi-Fi 600 — кабель главный, радио
   остаётся живым резервом;
3. адрес: у провода другой MAC (84:47:09:76:3a:11) — в Xiaomi перевесить
   резервирование 192.168.2.137 с Wi-Fi-MAC на проводной **после** проверки
   ssh по временному адресу; затем обновить аренды;
4. через пару спокойных дней можно снять заплатку `wifi-keepalive`.

## Подготовка второго сервера к переезду (без монитора)

1. **Не переключать сеть, а добавить вторую**: в netplan обе точки доступа —
   домашняя и второго дома; сервер сам цепляется к той, что слышит. Правки —
   только через `netplan try`;
2. **avahi-daemon** — после переезда сервер находится как
   `ssh user@имяхоста.local`, какой бы адрес ни выдал чужой роутер;
3. **страховочный трос**: на ethernet-порту `link-local: [ipv4]` — прямой
   кабель ноутбук↔сервер даёт ssh через 169.254.x.x + mDNS без всякого
   роутера;
4. **репетиция**: раздать с телефона точку с SSID/паролем второго дома —
   сервер должен подцепиться, не выходя из комнаты.

## Порядок работ

1. Подготовить второй сервер (netplan + avahi + link-local), репетиция с
   телефоном.
2. Провод acer ↔ Xiaomi, закрепление адреса.
3. Перевезти второй сервер, поднять Frigate + камеры (подсеть 192.168.3.0/24).
4. Хаб: mosquitto + ntfy на втором; acer — клиентом; уведомления в две трубы.
5. Вкладка «Калитка 2» в админке acer; ночной rsync архива.

## Открытые вопросы

- модель камеры второй калитки и чем открывается вторая калитка (реле?
  аналог SX120KW?).
