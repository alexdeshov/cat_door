# Идентификация котов

## Назначение

Контур идентификации работает полностью локально:

1. Узел записывает события прохода.
2. В веб-интерфейсе владелец отмечает несколько проходов одного кота и задаёт имя.
3. Набор собирается на узле фоновым процессом и забирается на MacBook M5.
4. На MacBook обучается **пространство эмбеддингов** для ракурсов `face` и
   `side` (с 2026-08-11 рабочая схема; классификатор остаётся запасной веткой).
   Эталон кота — среднее его векторов; «чужой» получается порогом, а не классом.
5. Модели экспортируются в ONNX и переносятся на узел.
6. Recorder выполняет инференс через OpenVINO и показывает имя только выше
   заданного порога.

Если порог не пройден, результат всегда `неизвестный кот` — защёлка по нему не
открывается. Пополнение памяти без макбука: кнопка «Запомнить заново»
прогоняет свежую разметку через стоящую модель и пересчитывает эталоны прямо
на узле, с автоматическим откатом, если новые эталоны хуже прежних.

Кадры, где детектор видит **двух котов сразу**, в наборы не попадают и
считаются отдельно (`excluded_two_cats`): имя у прохода одно, а котов в кадре
несколько, и кроп с изрядной вероятностью достался бы не тому.

## Разметка одинаковых проходов

В разделе «Сохранённые события»:

1. Просмотреть обе записи каждого события.
2. Отметить флажками только проходы одного и того же кота.
3. Ввести его имя.
4. Нажать «Объединить выбранные для обучения».

Проход является минимальной независимой единицей. Кадры одного прохода не попадают в разные
части train/validation/test. Не объединять сомнительные проходы.

## Минимальный набор

Для первого содержательного эксперимента нужны минимум два известных кота. На каждого:

- не менее 100 независимых событий;
- разные дни, освещение и направления движения;
- примерно 500 кадров с каждой полезной камеры.

Также нужен отдельный набор чужих котов для настройки open-set порога.

## Единый контракт изображения

Runtime и подготовка датасета используют функции из
`src/inference/preprocessing.py`:

1. Детектор получает пропорционально уменьшенный квадратный вход с полями;
   размер берётся из `input.shape` manifest (`320×320` у baseline).
2. Выбирается самая уверенная рамка `cat`, достигшая порога конкретной камеры.
3. Рамка пересчитывается в исходные координаты, расширяется на 20% с каждой
   стороны и ограничивается границами кадра.
4. Классификатор получает только этот кроп без полей, изменяет его размер до
   `image_size` модели и нормализует каналами ImageNet: mean
   `0.485/0.456/0.406`, std `0.229/0.224/0.225`.

Если для камеры включён ROI, он одинаково применяется к runtime и подготовке
датасета до масштабирования детектора. Общая функция преобразует координаты
рамки из входа модели через ROI обратно в полный кадр, поэтому identity-кроп
и рамка на полнокадровом preview остаются на правильном месте.

При экспорте набора на MacBook и при экспериментальном локальном обучении
извлечённые кадры сначала обрабатываются локальным
`models/cat-detector.onnx`. В манифест попадают только сохранённые кропы.
Кадры без уверенной рамки удаляются из создаваемого набора и учитываются в
`dataset-report.json` как `detector_crops.excluded_no_confident_box`; это не
происходит молча. Сам ONNX-детектор в экспорт для MacBook не включается.

## Отчёт обучения

Веб-интерфейс показывает отдельный отчёт локального экспериментального запуска:

- число независимых проходов и кадров;
- распределение проходов по именам;
- число кадров каждого ракурса;
- текущую модель, эпоху и средний training loss;
- validation accuracy после завершения;
- предупреждения о недостатке известных или чужих котов.

Запуск с малым набором не блокируется, поскольку он полезен для проверки pipeline, но отчёт
помечает такой набор как непригодный для эксплуатации. Высокая validation accuracy на нескольких
проходах не считается подтверждением качества: соседние условия съёмки слишком похожи, а
open-set поведение на чужих котах не проверено.

## Обучение на MacBook M5

Собрать набор кнопкой «Собрать набор для MacBook» (фоновый процесс, около
часа), скачать готовый архив кнопкой «Скачать собранный», распаковать и
установить зависимости `training`. Конвейер `identity_pipeline` делает это сам:
запускает сборку, ждёт опросом и берёт готовый архив, если тот моложе шести
часов. Для каждого доступного ракурса:

```bash
python -m training.train_embeddings DATASET/dataset.jsonl DATASET \
  OUTPUT/face.pt --view face --epochs 20 --image-size 160 \
  --weights-path ~/CatDoorTraining/models/mobilenet-v3-small-imagenet.pth
python -m training.export_onnx OUTPUT/face.pt OUTPUT/face-identity.onnx \
  --model-info OUTPUT/face-identity.json
```

(запасная ветка классификатора — `training.train_classifier`, те же аргументы)

Для `side` команды аналогичны с `--view side`. Обучение использует MPS, если он доступен.
Сырые данные, видео и обученные веса в Git не добавляются.
Начальные веса — официальный ImageNet-претрен MobileNetV3 Small. Их разрешено
один раз скачать на MacBook либо указать локальным `--weights-path`; без сети и
без локальных/cache-весов обучение не начинается. Безопасные аугментации меняют
яркость, контраст, масштаб кропа и слегка поворачивают его. Горизонтальное
отражение не применяется.

## Одной командой

Весь путь от разметки до пакета модели делает `scripts/identity_pipeline.py`,
запущенный из окружения обучения на MacBook:

```bash
cd ~/Documents/GitHub/cat_door
source .venv-training/bin/activate
python -m scripts.identity_pipeline all --cats Черныш,Яся
```

Имена в `--cats` пишутся через пробел или запятую — принимаются обе формы.
`--rebuild-export` пересобирает набор, даже если готовый свежий;
`--allow-experimental` ставит пакет вопреки непройденной приёмке.

Стадии вызываются и по отдельности: `fetch` — забрать набор с узла, `train` —
обучить оба ракурса и собрать пакет, `install` — отвезти модели на узел.
Установка сама проверяет два условия и отказывается без `--allow-experimental`:
набор не меньше рекомендованного и приёмка на отложенных проходах пройдена.
Активацию скрипт не делает — пути к моделям лежат в `/etc/catdoor/catdoor.env`
под root, а раздавать права ради удобства нельзя: у админки нет
аутентификации. Вместо этого печатается готовая команда.

Перед первым запуском на узле должен лежать детектор котов
`/opt/catdoor/models/cat-detector.onnx` — без него экспорт не соберёт ни одного
кропа. Он готовится на MacBook и переносится один раз:

```bash
python -m scripts.prepare_cat_detector
scp models/cat-detector.onnx models/cat-detector.json УЗЕЛ:/opt/catdoor/models/
```

## Чему верить в отчётах

Смотреть надо на приёмку, а не на validation accuracy. Валидация состоит из
кадров тех же проходов, что и обучение: соседние секунды одной записи похожи
друг на друга сильнее, чем два прохода одного кота в разные дни. Разрыв
измерен 5 августа на наборе из 61 прохода: валидация показала 0.81 и 0.84,
приёмка на других проходах — 0.57 и 0.30. Второе и есть правда о модели.

Отсюда же требование к набору: не меньше сотни независимых проходов на кота.
Кот, снятый трижды, даёт красивую валидацию и не даёт ничего больше.

## Установка модели на узле

Скопировать пары `.onnx` + `.json` в локальный каталог `models/` и задать:

```dotenv
CATDOOR_IDENTITY_FACE_MODEL_PATH=models/face-identity.onnx
CATDOOR_IDENTITY_SIDE_MODEL_PATH=models/side-identity.onnx
CATDOOR_IDENTITY_CONFIDENCE_THRESHOLD=0.80
```

После перезапуска recorder веб-интерфейс показывает имя и уверенность. Порог `0.80` временный:
его нужно откалибровать на test-наборе с приоритетом минимального False Accept Rate.

Классификатор личности запускается только после того, как уверенность детектора
достигла порога, настроенного для конкретной камеры в админке. Общий устаревший
порог детекции на это решение не влияет.
Устройство OpenVINO задаётся общим явным параметром
`CATDOOR_DETECTOR_DEVICE`; автоматического переключения между GPU и CPU нет.
