# CatDoor AI

Локальная система визуальной идентификации домашних кошек и наблюдения за
участком. Всё работает на одном узле без облака. Система не только смотрит и
учится: калитка открывается по узнанному лицу, защёлка кошачьей дверцы
управляется из админки, автоматика открытия по коту встроена и включается
владельцем.

## Как это устроено сейчас

Узел — mini-PC (hostname `acer`) под Ubuntu Server 24.04. Камеры живут в
изолированной сети на отдельном интерфейсе; адреса им выдаёт `dnsmasq`, время —
`chrony` с этого же узла. Рядом в Docker подняты Frigate и брокер MQTT
(`docs/mqtt-broker.md`).

Контуров три, и они работают одновременно (замер 2026-08-05,
`docs/two-circuits-plan.md`):

- **Дверца** (этот репозиторий) — собственный конвейер: recorder ловит котов
  локальным детектором (ONNX/OpenVINO, видеоядро), опознаёт их эмбеддингами по
  эталонам и пишет проходы с предысторией. Роли камер: `face` — камера дверцы,
  `side` — подход. Решение об открытии защёлки принимается по живому кадру
  камеры дверцы.
- **Калитка 1** и **Регистратор** (репозиторий `gate_access`) — Frigate: люди,
  машины, распознавание лиц. Служба `catdoor-gate-access` ведёт журнал проходов
  калитки и открывает её по узнанному лицу импульсом на плату реле
  Waveshare (Modbus TCP); уведомления шлёт `catdoor-gate-notify`.

Состояние контуров сводит примиритель `catdoor-gate-sync`. Конфигурация Frigate
собирается из инвентаря камер автоматически, ручные разделы (лица, номера)
переживают пересборку.

Веб-админка на порту 8080: живые превью (по дешёвым субпотокам), разметка
проходов, инвентарь камер с поиском по сети, метрики моделей. Аутентификации
нет — доступ ограничен домашней сетью через `ufw`.

## Развёртывание

```sh
sudo ./install/install.sh
```

Скрипт создаёт пользователя `catdoor`, ставит systemd-юниты и включает
автозапуск. Службы объявлены `Type=notify` и перезапускаются сами. Камеры
задаются в `/etc/catdoor/catdoor.env` один раз — при первом старте из них
собирается инвентарь `runtime/cameras.json`, дальше всё редактируется на
вкладке «Камеры». Полная инструкция, включая DHCP/NTP для сети камер и
проверку перезагрузкой: `docs/deployment-ubuntu.md`; шпаргалка владельца:
`docs/operator-handbook.md`.

Обучение пространства эмбеддингов идёт на MacBook (PyTorch/MPS), модели
переносятся ONNX-пакетами с контрольными суммами. Весь путь от разметки до
пакета — одна команда из окружения обучения:

```sh
python -m scripts.identity_pipeline all --cats Черныш,Яся
```

Пополнение памяти макбука не требует: кнопка «Запомнить заново» в админке
пересчитывает эталоны котов прямо на узле по свежей разметке и сама
откатывается, если новые эталоны хуже прежних.

Установка сама отказывается от модели, не прошедшей приёмку на отложенных
проходах. Подробности: `docs/identity-training.md`,
`docs/model-training-and-acceptance.md`.

## Жёсткие ограничения

- никакого облачного инференса, RFID и меток — только зрение;
- механику коммутирует только плата реле Waveshare, в границах письменных
  разрешений владельца из `AGENTS.md`: импульс «кнопки выхода» калитки и
  защёлка дверцы, ничего больше; автоматика включается владельцем, умолчание
  всегда `off`;
- пароли, RTSP-адреса, IP камер, видео и база в Git не попадают.
