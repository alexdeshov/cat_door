# CatDoor AI

Локальная система визуальной идентификации домашних кошек и наблюдения за
участком. Всё работает на одном узле без облака; дверца пока не управляется —
система смотрит, записывает и учится.

## Как это устроено сейчас

Узел — mini-PC `gatekeeper` под Ubuntu Server 24.04. Камеры живут в
изолированной сети на отдельном интерфейсе; адреса им выдаёт `dnsmasq`, время —
`chrony` с этого же узла.

Контуров три, и они делят один процессор:

- **Дверца** (этот репозиторий) — собственный конвейер: recorder ловит котов
  локальным детектором (ONNX/OpenVINO CPU), пишет проходы с предысторией и
  копит датасет для идентификации. Роли камер: `face` — идентификация,
  `side` — подход.
- **Калитка 1** и **Регистратор** (репозиторий `gate_access`) — Frigate: люди,
  машины, распознавание лиц.

Кошачий контур и Frigate взаимоисключающие; переключатель — в шапке админки,
состояние сводит примиритель `catdoor-gate-sync`. Конфигурация Frigate
собирается из инвентаря камер автоматически, ручные разделы (лица, номера)
переживают пересборку.

Веб-админка на порту 8080: живые превью (по дешёвым субпотокам), разметка
проходов, инвентарь камер с поиском по сети, метрики моделей. Аутентификации
нет — доступ ограничен домашней сетью через `ufw`.

## Развёртывание

```sh
sudo ./install/install.sh
```

Скрипт создаёт пользователя `catdoor`, ставит systemd-юниты и включает
автозапуск. Службы объявлены `Type=notify` и перезапускаются сами. Камеры
задаются в `/etc/catdoor/catdoor.env` один раз — при первом старте из них
собирается инвентарь `runtime/cameras.json`, дальше всё редактируется на
вкладке «Камеры». Полная инструкция, включая DHCP/NTP для сети камер и
проверку перезагрузкой: `docs/deployment-ubuntu.md`; шпаргалка владельца:
`docs/operator-handbook.md`.

Обучение идёт на MacBook (PyTorch/MPS), модели переносятся ONNX-пакетами с
контрольными суммами. Весь путь от разметки до пакета — одна команда:

```sh
python -m scripts.identity_pipeline all
```

Установка сама отказывается от модели, не прошедшей приёмку на отложенных
проходах. Подробности: `docs/identity-training.md`,
`docs/model-training-and-acceptance.md`.

## Жёсткие ограничения

- никакого облачного инференса, RFID и меток — только зрение;
- дверь не управляется до отдельного разрешения владельца; силовая механика —
  только через будущий ESP32/Arduino;
- пароли, RTSP-адреса, IP камер, видео и база в Git не попадают.
