# Инструкции для Codex

Перед любой работой обязательно прочитать:

1. `PROJECT_BRIEF.md`
2. `README.md`
3. последнюю запись в `docs/session-history.md`, если файл существует
4. соответствующую документацию в `docs/`

## Жёсткие ограничения

- Не использовать облачный инференс.
- Не добавлять RFID, NFC, ошейники или имплантируемые метки.
- Не коммитить секреты, RTSP-пароли, токены, видео, полный датасет или резервные копии базы.
- Не управлять любыми каналами реле, кроме перечисленных ниже, до отдельного
  письменного разрешения владельца проекта.
- **Разрешено с 2026-08-11** (письменное разрешение владельца, границы ниже):
  импульс на реле калитки платы Waveshare — и только он.
  - Разрешено: замыкание входа «кнопка выхода» контроллера Novicam SX120KW на
    время до нескольких секунд. Замком по-прежнему распоряжается сам SX120KW;
    в цепь замка система не вмешивается.
  - Не разрешено: остальные каналы платы, любые команды, кроме импульса на
    настроенном канале калитки.
  - Условия: каждое срабатывание пишется в журнал проходов и уходит
    уведомлением в Телеграм. Импульс задаётся одной командой, которая сама
    размыкает контакт, — смерть процесса не должна оставлять калитку
    разомкнутой.
  - Автоматическое открытие по лицу включается владельцем самостоятельно
    переключателем режима в админке. Четыре условия выхода из
    `docs/gate-access-plan.md` (ноль «открыл бы» на чужих, все свои приходы в
    журнале, измеренная задержка, понятный объём выборки) остаются
    рекомендацией: их стоит проверить по журналу, но решение за владельцем.
    Умолчание системы — `off`, и оно не меняется кодом.
- **Разрешено с 2026-08-12** (письменное разрешение владельца, границы ниже):
  импульс на реле 2 — защёлка кошачьей дверцы.
  - Разрешено: подача питания на защёлку 12 В через сухой контакт реле 2.
  - Не разрешено: остальные каналы платы, любые команды, кроме открытия
    дверцы на заданное время.
  - Условия: каждое срабатывание пишется в журнал и уходит уведомлением в
    Телеграм; открытие задаётся одной командой, которая сама снимает питание, —
    смерть процесса не должна оставить защёлку под током.
  - Умолчание — `off`. Автоматическое открытие по коту включает владелец сам,
    и до этого система работает в режиме «открыла бы».
- Силовую механику коммутирует плата реле Waveshare — она и есть то отдельное
  устройство, о котором говорит правило выше. Отдельный ESP32 или Arduino для
  этого не заводится: плата уже стоит, разговаривает по Modbus и разделяет
  контуры сухими контактами.
- Инференс выполняется через OpenVINO; с 2026-08-08 детектор работает на
  встроенном видеоядре узла (13.5 мс на кадр против 18.5 на процессоре),
  процессорный путь остаётся запасным. Внешние GPU и облачный инференс
  не используются.
- Обучение выполнять на MacBook M5.
- Формат передачи моделей на сервер — ONNX.
- Не тянуть `main` на работающий Windows-моноблок. Он заморожен на теге
  `windows-runtime-final` до переезда на Ubuntu; начиная с PR #15 `main`
  не работает под Windows. Срочные правки для моноблока — веткой от тега.
- Падение веб-интерфейса не должно останавливать запись и инференс.
- Все потенциально опасные действия требуют явного подтверждения.

## Правила разработки

- Делать небольшие, проверяемые изменения.
- Для каждой новой функции добавлять тесты.
- Не менять архитектуру без объяснения причин.
- Не выполнять команды администратора без подтверждения.
- Не изменять `main` напрямую: использовать отдельную ветку и pull request.
- Обновлять документацию вместе с кодом.
- При изменении схемы базы создавать миграцию.
- Не зашивать IP-адреса, RTSP URL и учётные данные в код.
- Все настройки должны передаваться через конфигурацию или веб-интерфейс.
- Runtime — Ubuntu Server 24.04, training — macOS. Совместимость с Windows
  в runtime больше не поддерживается и не восстанавливается.

## История сессий

- Перед финальным ответом каждой рабочей сессии обновлять `docs/session-history.md`,
  если в сессии изменялись файлы, выполнялись проверки или принимались
  архитектурные и процессные решения.
- Добавлять одну краткую запись по шаблону из файла: цель, сделано, решения,
  изменённые файлы, проверки и следующий шаг.
- Если работа не завершена или заблокирована, явно записывать текущий статус и
  причину остановки.
- Не создавать запись для простого ответа на вопрос, если репозиторий не менялся
  и новых проектных решений не было.
- Журнал вести в режиме append-only. Старые записи не переписывать, кроме
  исправления явной фактической ошибки.
- Не записывать в историю секреты, RTSP URL, IP-адреса камер, учётные данные,
  токены, персональные данные и содержимое реальных видео.
- Обновление истории включать в ту же ветку и pull request, что и основную работу
  сессии.
